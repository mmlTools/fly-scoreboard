How to Setup

Fly manages one shared scoreboard state. You create and arrange the modular Browser Sources yourself in OBS.

Choose the writable template folder

  1. Open the Fly Scoreboard dock.
  2. Click Template Folder….
  3. Choose the writable Modular Football folder itself, or the root directory of your custom setup. Do not choose its parent directory.
  4. The active template name appears as plain text. There is no source or template dropdown.
  5. Click Open whenever you need to inspect the active files.

The chosen folder is the setup's state hub. Fly writes plugin.json there and broadcasts the same state over ws://127.0.0.1:4457. The plugin contains no OBS source selector and never creates, selects, renames, resizes, or edits an OBS Browser Source.

Add the football modules to OBS

Create a separate local-file Browser Source for every panel you want:

Suggested source nameLocal filePurpose
Football – Scoreboardindex.htmlTeams, score, main timer, period
Football – Foulsfouls.htmlHome/guest foul totals
Football – Cardscards.htmlYellow and red card totals
Football – Cornerscorners.htmlHome/guest corner totals
  1. In OBS Sources, choose + → Browser.
  2. Enable Local file and select one HTML file from the active template folder.
  3. Set the source to the same width and height as the OBS base canvas.
  4. Resize and position that panel in the OBS preview.
  5. Repeat for each additional module. You can show, hide, crop, animate, and reuse each source independently.
All four pages use the same script.js, style.css, WebSocket, and plugin.json. A score or team update in the dock reaches every open module.

Required football field order

The default football package creates these Team Stats. Keep the first five slots in this order:

  1. score – Score
  2. fouls – Fouls
  3. yellow_cards – Yellow Cards
  4. red_cards – Red Cards
  5. corners – Corners

The runtime exposes these stable aliases through fields_by_key, so the bundled pages use bindings such as {{fields_by_key.fouls.x}}.

Recommended Browser Source settings

  • Custom CSS: leave empty; use the package's style.css.
  • Shutdown source when not visible: disable it if hidden timers must keep rendering continuously.
  • FPS: 30 is sufficient for most panels; use 60 for animation-heavy themes.
  • Refresh cache: use after editing HTML, CSS, or JavaScript.

Package structure

Modular Football/
  manifest.ini
  index.html       # scoreboard only
  fouls.html       # fouls only
  cards.html       # cards only
  corners.html     # corners only
  style.css        # shared presentation
  script.js        # shared Fly runtime
  plugin.json      # shared state written by Fly

Troubleshooting

  • No updates: confirm the dock WebSocket status and that every HTML file comes from the active template folder.
  • A module is empty: confirm its required Team Stat exists and is visible.
  • Fallback does not work: keep plugin.json beside all module HTML files.
  • Wrong team side: use team_x/team_y and fields_by_key.*.x/y, which honor side swapping.
